# Конфигурация фильтрации задач

## Принцип работы бота

Бот работает как **временный бизнес-аналитик**, который:
1. Принимает задачи на себя (исполнитель/соисполнитель)
2. Собирает и уточняет требования у постановщика
3. Формирует полное ТЗ
4. Передаёт задачу реальному исполнителю

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  Постановщик    │────►│   БОТ (BA)      │────►│  Исполнитель    │
│  создаёт задачу │     │  собирает ТЗ    │     │  получает ТЗ    │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

## Какие задачи обрабатывает бот

### Условия входа (все должны выполняться):

```yaml
trigger_conditions:
  # Бот должен быть назначен на задачу
  bot_role:
    - responsible      # Исполнитель
    - accomplice       # Соисполнитель

  # Статусы задач для обработки
  task_status:
    - 2  # Ждёт выполнения
    - 3  # Выполняется

  # Исключения
  exclude:
    - tasks_with_tag: "ready_to_work"  # Уже обработанные
    - tasks_with_tag: "skip_ba"        # Помечены для пропуска
    - created_by: BOT_USER_ID          # Созданные самим ботом
```

### Условия выхода (любое):

```yaml
exit_conditions:
  # Бот завершает работу когда:
  - description_complete: true           # ТЗ полное (score >= 80)
    AND tag_added: "ready_to_work"       # Тег проставлен
    AND one_of:
      - responsible_changed: true        # Исполнитель изменён
      - executor_confirmed: true         # Исполнитель подтвердил
```

## Сценарии назначения бота

### Сценарий A: Бот как исполнитель

```
1. Постановщик создаёт задачу → назначает бота исполнителем
2. Бот анализирует → задаёт вопросы
3. Постановщик отвечает
4. Бот формирует ТЗ → ставит тег "ready_to_work"
5. Постановщик меняет исполнителя на реального
6. Бот отписывается от задачи
```

**Когда использовать:** Постановщик не знает, кому назначить задачу, или хочет сначала проработать требования.

### Сценарий B: Бот как соисполнитель

```
1. Постановщик создаёт задачу → назначает исполнителя + бота соисполнителем
2. Бот анализирует → задаёт вопросы
3. Постановщик отвечает
4. Бот формирует ТЗ → ставит тег "ready_to_work"
5. Исполнитель подтверждает принятие (комментарий/реакция)
6. Бот удаляется из соисполнителей
```

**Когда использовать:** Исполнитель уже известен, но нужна помощь в сборе требований.

## API проверки роли бота

### Проверка исполнителя:
```javascript
// task.responsibleId === BOT_USER_ID
$json.result.task.responsibleId === $env.BOT_USER_ID
```

### Проверка соисполнителя:
```javascript
// BOT_USER_ID in task.accomplices
$json.result.task.accomplices?.includes($env.BOT_USER_ID)
```

### Комбинированная проверка:
```javascript
const botId = $env.BOT_USER_ID;
const task = $json.result.task;
const isBotAssigned =
  task.responsibleId === botId ||
  (task.accomplices && task.accomplices.includes(botId));
```
