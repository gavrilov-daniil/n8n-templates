# Конфигурация тегов

Фиксированный список тегов для классификации задач ИИ Бизнес-аналитиком.

## Правила тегирования

1. **Статус обработки** - служебный, управляется ботом автоматически
2. **Тип задачи** - обязательно, строго 1 тег
3. **Приоритет** - обязательно, строго 1 тег
4. **Область** - опционально, 0-2 тега
5. **Бизнес-модуль** - опционально, 0-2 тега

**Максимум тегов на задачу:** 7 (включая служебный)

---

## Список тегов

### Статус обработки (служебные, управляются ботом)

| Тег | Описание | Когда ставится |
|-----|----------|----------------|
| `ba_analyzing` | Бот анализирует | При получении задачи ботом |
| `ba_pending` | Ожидает ответа | После отправки вопросов постановщику |
| `ready_to_work` | Готово к работе | ТЗ сформировано, можно приступать |
| `skip_ba` | Пропустить анализ | Ставится вручную, бот игнорирует задачу |

**Важно:**
- Эти теги управляются ТОЛЬКО ботом (кроме `skip_ba`)
- При переходе между статусами старый тег удаляется
- `ready_to_work` - финальный статус, бот больше не трогает задачу

### Тип задачи (обязательно)

| Тег | Описание | Когда использовать |
|-----|----------|-------------------|
| `bug` | Ошибка, дефект | Что-то работает неправильно, сломалось |
| `feature` | Новый функционал | Создание чего-то нового с нуля |
| `improvement` | Улучшение | Доработка существующего функционала |
| `research` | Исследование | Анализ, изучение, подготовка решения |
| `support` | Поддержка | Консультация, помощь, настройка |

### Приоритет (обязательно)

| Тег | Описание | Когда использовать |
|-----|----------|-------------------|
| `critical` | Критический | Блокер, не работает продакшен, срочно |
| `high` | Высокий | Важно, влияет на бизнес-процессы |
| `medium` | Средний | Стандартная задача (по умолчанию) |
| `low` | Низкий | Можно отложить, бэклог |

### Область (опционально)

| Тег | Описание | Когда использовать |
|-----|----------|-------------------|
| `frontend` | Интерфейс | UI, дизайн, вёрстка, формы |
| `backend` | Сервер | Логика, API, обработка данных |
| `database` | База данных | Структура БД, запросы, миграции |
| `integration` | Интеграции | Связь с внешними системами |
| `mobile` | Мобильное | iOS, Android приложения |
| `infrastructure` | Инфраструктура | Сервера, деплой, DevOps |

### Бизнес-модуль (опционально)

| Тег | Описание | Когда использовать |
|-----|----------|-------------------|
| `sales` | Продажи | Сделки, воронка, менеджеры |
| `marketing` | Маркетинг | Реклама, лиды, рассылки |
| `finance` | Финансы | Счета, оплаты, бухгалтерия |
| `hr` | Персонал | Сотрудники, кадры, HR |
| `operations` | Операции | Логистика, склад, процессы |

## Примеры тегирования

### Пример 1: Задача в процессе анализа
```
Задача: "Не загружается отчёт по продажам за декабрь"
Теги: ba_analyzing, bug, high, frontend, sales
       ↑ служебный   ↑ тип  ↑ приоритет ↑ область ↑ модуль
```

### Пример 2: Задача ожидает ответа постановщика
```
Задача: "Интеграция с 1С для синхронизации остатков"
Теги: ba_pending, feature, medium, integration, operations
```

### Пример 3: Задача готова к работе
```
Задача: "Сайт недоступен, ошибка 500"
Теги: ready_to_work, bug, critical, backend, infrastructure
```

### Пример 4: Задача пропущена ботом (ручной тег)
```
Задача: "Проанализировать возможность внедрения CRM"
Теги: skip_ba, research, low, sales
```

### Пример 5: Полный цикл жизни тегов
```
1. Создана задача → бот получает → [ba_analyzing]
2. Бот задал вопросы → [ba_pending, feature, medium, frontend, sales]
3. Постановщик ответил → бот обновил → [ba_analyzing, feature, medium, frontend, sales]
4. ТЗ готово → [ready_to_work, feature, medium, frontend, sales]
```

## Маппинг приоритетов Битрикс24

| Приоритет в Битрикс24 | Тег |
|-----------------------|-----|
| Низкий (0) | `low` |
| Средний (1) | `medium` |
| Высокий (2) | `high` |
| Срочный (3) | `critical` |

При наличии слов "срочно", "ASAP", "блокер", "не работает" → `critical`
