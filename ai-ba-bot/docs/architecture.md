## Компоненты системы

### 1. Триггеры (Входные точки)

| Триггер | Описание | Когда использовать |
|---------|----------|-------------------|
| **Webhook** | Битрикс24 отправляет событие при создании/изменении задачи | Рекомендуется для production |
| **Schedule Poll** | n8n периодически опрашивает API на наличие новых задач | Если webhooks недоступны |
| **Manual** | Ручной запуск для тестирования | Разработка и отладка |

### 2. Основные Workflows

#### 2.1 Workflow: Анализ новой задачи
```
Trigger (New Task)
    → Fetch Task Details
    → AI: Analyze Completeness
    → IF sufficient: Tag & Notify
    → ELSE: Generate Questions → Post Comment
```

#### 2.2 Workflow: Обработка ответов
```
Trigger (New Comment)
    → Check if awaiting response
    → AI: Parse Answers
    → AI: Generate Updated Description
    → Update Task
    → AI: Classify Tags
    → Add Tags
    → Notify All Parties
```

#### 2.3 Workflow: Периодическая проверка
```
Schedule (hourly)
    → Fetch tasks with #требует_уточнения
    → Check last comment age
    → IF > 24h: Send reminder
    → IF > 72h: Escalate to manager
```

### 3. Хранение состояния

Для отслеживания задач, ожидающих ответа:

**Вариант A: Теги в Битрикс24**
- `#требует_уточнения` - ожидает ответ
- `#проанализировано` - обработано ИИ
- Просто, но ограничено

**Вариант B: Внешняя БД (рекомендуется)**
- PostgreSQL / SQLite через n8n
- Таблица `pending_tasks`:
  ```sql
  CREATE TABLE pending_tasks (
    task_id INTEGER PRIMARY KEY,
    created_at TIMESTAMP,
    questions_sent_at TIMESTAMP,
    status VARCHAR(50),
    context JSONB
  );
  ```

**Вариант C: n8n Static Data**
- Встроенное хранилище n8n
- Подходит для небольших объёмов

### 4. Интеграция с LLM

#### Поддерживаемые провайдеры:

| Провайдер | Node в n8n | Особенности |
|-----------|------------|-------------|
| OpenAI | OpenAI Node | GPT-4, GPT-3.5-turbo |
| Anthropic | HTTP Request | Claude 3.5 Sonnet |
| Ollama | HTTP Request | Локальные модели (Llama, Mistral) |
| OpenRouter | HTTP Request | Доступ к разным моделям |

#### Рекомендуемые модели:

- **Анализ задач:** GPT-4 / Claude 3.5 Sonnet (высокое качество)
- **Генерация вопросов:** GPT-3.5-turbo (достаточно, дешевле)
- **Классификация тегов:** GPT-3.5-turbo или локальная модель

## Потоки данных

### Поток 1: Новая задача

```
1. Битрикс24 → Webhook → n8n получает событие
2. n8n → Битрикс24 API: tasks.task.get (полные данные)
3. n8n → LLM: Анализ описания
4. LLM → n8n: Результат {complete: false, missing: [...]}
5. n8n → LLM: Генерация вопросов
6. LLM → n8n: Текст вопросов
7. n8n → Битрикс24 API: task.commentitem.add
8. n8n → БД: Сохранить pending_task
```

### Поток 2: Получен ответ

```
1. Битрикс24 → Webhook → n8n получает комментарий
2. n8n → БД: Проверить pending_task
3. n8n → Битрикс24 API: Получить все комментарии
4. n8n → LLM: Обработать диалог
5. LLM → n8n: Обновлённое описание
6. n8n → Битрикс24 API: tasks.task.update
7. n8n → LLM: Классификация тегов
8. LLM → n8n: Список тегов
9. n8n → Битрикс24 API: Добавить теги
10. n8n → Битрикс24 API: im.notify (уведомления)
11. n8n → БД: Удалить pending_task
```

## Обработка ошибок

### Retry стратегия

```javascript
// Настройки в n8n node
{
  "retry": {
    "maxRetries": 3,
    "waitBetweenRetries": 5000,
    "backoffFactor": 2
  }
}
```

### Типичные ошибки

| Ошибка | Причина | Решение |
|--------|---------|---------|
| 401 Unauthorized | Истёк токен Битрикс24 | Обновить OAuth токен |
| 429 Too Many Requests | Лимит API | Добавить задержки |
| 500 LLM Error | Проблема с AI провайдером | Retry или fallback |
| Timeout | Долгий ответ LLM | Увеличить timeout |

### Логирование

Рекомендуется логировать:
- Все входящие задачи
- Решения ИИ (достаточно/недостаточно)
- Отправленные вопросы
- Обновления задач
- Ошибки с контекстом

## Безопасность

### Рекомендации:

1. **Хранение credentials** - использовать n8n Credentials, не хардкодить
2. **Webhook секреты** - валидировать подпись от Битрикс24
3. **Rate limiting** - ограничить количество обрабатываемых задач
4. **Input validation** - проверять данные перед отправкой в LLM
5. **PII** - не логировать персональные данные без необходимости

### Права в Битрикс24

Минимально необходимые права:
- `task` - чтение и запись задач
- `task.comment` - работа с комментариями
- `user` - получение информации о пользователях
- `im` - отправка уведомлений

## Масштабирование

### Для небольших команд (до 50 задач/день):
- Один n8n instance
- SQLite для состояния
- OpenAI API

### Для средних команд (50-500 задач/день):
- n8n с PostgreSQL
- Redis для очередей
- Несколько workers

### Для крупных организаций (500+ задач/день):
- n8n в Kubernetes
- Отдельный LLM (vLLM, Ollama cluster)
- Распределённая обработка
