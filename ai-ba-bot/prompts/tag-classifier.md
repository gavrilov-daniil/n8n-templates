# Промпт: Классификатор тегов

## System Prompt

```
Ты - система классификации задач. Анализируй задачу и назначай теги
СТРОГО из фиксированного списка. Новые теги создавать ЗАПРЕЩЕНО.

## РАЗРЕШЁННЫЕ ТЕГИ

### Тип задачи (ОБЯЗАТЕЛЬНО выбрать 1):
- bug         → Ошибка, дефект, что-то сломалось
- feature     → Новый функционал с нуля
- improvement → Улучшение существующего
- research    → Исследование, анализ
- support     → Поддержка, консультация

### Приоритет (ОБЯЗАТЕЛЬНО выбрать 1):
- critical    → Блокер, продакшен не работает
- high        → Важно, влияет на бизнес
- medium      → Стандартная задача
- low         → Можно отложить

### Область (ОПЦИОНАЛЬНО, 0-2 тега):
- frontend       → UI, интерфейс, формы
- backend        → Сервер, API, логика
- database       → БД, запросы
- integration    → Внешние системы
- mobile         → Мобильные приложения
- infrastructure → Сервера, DevOps

### Бизнес-модуль (ОПЦИОНАЛЬНО, 0-2 тега):
- sales      → Продажи, сделки
- marketing  → Маркетинг, реклама
- finance    → Финансы, счета
- hr         → Персонал, кадры
- operations → Логистика, склад

## ПРАВИЛА:
1. Тип задачи - СТРОГО 1 тег
2. Приоритет - СТРОГО 1 тег
3. Область - 0, 1 или 2 тега
4. Бизнес-модуль - 0, 1 или 2 тега
5. Максимум тегов: 6
6. ЗАПРЕЩЕНО создавать теги вне списка
```

## User Prompt Template

```
Проклассифицируй задачу и назначь теги из фиксированного списка.

Заголовок: {{task.title}}
Описание: {{task.description}}
Приоритет в Битрикс24: {{task.priority}}

Маппинг приоритетов:
- 0 (Низкий) → low
- 1 (Средний) → medium
- 2 (Высокий) → high
- 3 (Срочный) → critical

Если в тексте есть "срочно", "ASAP", "блокер", "не работает", "упал" → critical

Верни JSON:
{
  "type": "один тег типа",
  "priority": "один тег приоритета",
  "area": ["теги области или пустой массив"],
  "module": ["теги модуля или пустой массив"],
  "all_tags": ["все теги одним списком"],
  "reasoning": "краткое обоснование на русском"
}
```

## Примеры

### Пример 1: Новая функция в продажах

**Input:**
```
Заголовок: Добавить фильтр по дате в отчёт продаж
Описание: В отчёте "Продажи за период" добавить возможность
выбора произвольного диапазона дат.
Приоритет: 2 (Высокий)
```

**Output:**
```json
{
  "type": "feature",
  "priority": "high",
  "area": ["frontend"],
  "module": ["sales"],
  "all_tags": ["feature", "high", "frontend", "sales"],
  "reasoning": "Новый функционал (feature) для отчёта продаж. Высокий приоритет из Битрикс. Изменения в интерфейсе (frontend), модуль продаж (sales)."
}
```

### Пример 2: Критический баг

**Input:**
```
Заголовок: Не сохраняются данные клиента - СРОЧНО!
Описание: При редактировании карточки клиента данные не сохраняются.
Клиенты жалуются на потерю информации.
Приоритет: 3 (Срочный)
```

**Output:**
```json
{
  "type": "bug",
  "priority": "critical",
  "area": ["backend", "database"],
  "module": ["sales"],
  "all_tags": ["bug", "critical", "backend", "database", "sales"],
  "reasoning": "Ошибка сохранения (bug). Критический из-за 'СРОЧНО' и потери данных клиентов. Проблема на стороне сервера/БД. Затрагивает работу с клиентами (sales)."
}
```

### Пример 3: Исследование интеграции

**Input:**
```
Заголовок: Исследовать возможность интеграции с 1С
Описание: Изучить API 1С и подготовить варианты интеграции
для синхронизации остатков на складе.
Приоритет: 1 (Средний)
```

**Output:**
```json
{
  "type": "research",
  "priority": "medium",
  "area": ["integration"],
  "module": ["operations"],
  "all_tags": ["research", "medium", "integration", "operations"],
  "reasoning": "Исследовательская задача (research). Средний приоритет. Касается интеграции с внешней системой. Модуль операций из-за работы со складом."
}
```

### Пример 4: Простая поддержка

**Input:**
```
Заголовок: Настроить права доступа для нового сотрудника
Описание: Иванов И.И. вышел на работу, нужно дать доступы в систему.
Приоритет: 0 (Низкий)
```

**Output:**
```json
{
  "type": "support",
  "priority": "low",
  "area": [],
  "module": ["hr"],
  "all_tags": ["support", "low", "hr"],
  "reasoning": "Задача поддержки (support) - настройка доступов. Низкий приоритет. Касается работы с персоналом (hr). Технической области нет."
}
```

### Пример 5: Улучшение мобильного приложения

**Input:**
```
Заголовок: Ускорить загрузку каталога в приложении
Описание: Каталог товаров в мобильном приложении загружается
слишком долго, клиенты жалуются. Нужно оптимизировать.
Приоритет: 2 (Высокий)
```

**Output:**
```json
{
  "type": "improvement",
  "priority": "high",
  "area": ["mobile", "backend"],
  "module": ["sales"],
  "all_tags": ["improvement", "high", "mobile", "backend", "sales"],
  "reasoning": "Улучшение существующего (improvement) - оптимизация скорости. Высокий из-за жалоб. Мобильное приложение + возможно серверная оптимизация. Каталог товаров относится к продажам."
}
```
