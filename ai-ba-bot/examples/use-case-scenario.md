# Кейс работы ИИ Бизнес-аналитика

## Принцип работы

Бот обрабатывает **только те задачи, где он назначен исполнителем или соисполнителем**.
Это позволяет контролировать, какие задачи проходят через бизнес-анализ.

---

## Сценарий A: Бот как исполнитель

### Исходная ситуация

**Постановщик:** Иванов Пётр (Руководитель отдела продаж)
**Исполнитель:** ИИ Бизнес-аналитик (бот)

Пётр не знает, кому назначить задачу, или хочет сначала проработать требования.
Он создаёт задачу и назначает бота исполнителем:

```
Заголовок: Добавить отчёт по продажам
Описание: Нужен новый отчёт для менеджеров
Приоритет: Высокий
Исполнитель: ИИ Бизнес-аналитик ← БОТ
Дедлайн: через 2 недели
```

---

### Этап 1: Бот получает задачу

**Триггер:** Webhook получает событие о новой/изменённой задаче

**Проверки бота:**
```javascript
// Проверяем, назначен ли бот исполнителем или соисполнителем
const botId = "BOT_USER_ID";
const task = event.data.task;

const isBotAssigned =
  task.responsibleId === botId ||
  task.accomplices?.includes(botId);

// Проверяем, не обработана ли задача уже
const isAlreadyProcessed =
  task.tags?.includes("ready_to_work") ||
  task.tags?.includes("skip_ba");

if (isBotAssigned && !isAlreadyProcessed) {
  // Обрабатываем задачу
}
```

**Действие:** Бот ставит тег `ba_analyzing`

---

### Этап 2: Анализ задачи

ИИ оценивает полноту описания:

| Критерий | Статус | Оценка |
|----------|--------|--------|
| Цель задачи | Частично | 10/20 |
| Ожидаемый результат | Отсутствует | 0/20 |
| Контекст | Частично | 5/20 |
| Критерии приёмки | Отсутствует | 0/20 |
| Ограничения | Частично | 5/20 |
| **ИТОГО** | | **20/100** |

**Решение:** Score < 80 → нужны уточнения

---

### Этап 3: Отправка вопросов

Бот формирует и отправляет комментарий:

```markdown
Здравствуйте, Пётр!

Я - ИИ Бизнес-аналитик. Для качественной проработки задачи
"Добавить отчёт по продажам" мне нужны уточнения:

1. **Цель отчёта:** Для каких бизнес-решений будет использоваться?
   (контроль KPI / прогнозирование / мотивация менеджеров)

2. **Какие данные включить:**
   - Объём продаж (в рублях, штуках)?
   - По каким менеджерам/отделам?
   - Сравнение с планом?

3. **Период:** За какой период нужны данные?

4. **Формат:** Как удобнее получать отчёт?
   (таблица в Битрикс / Excel / дашборд)

5. **Доступ:** Кто должен видеть отчёт?

6. **Регулярность:** Разово или на постоянной основе?

Пожалуйста, ответьте на вопросы в комментарии.

---
*ИИ Бизнес-аналитик*
```

**Действие:** Бот меняет тег `ba_analyzing` → `ba_pending`

---

### Этап 4: Ожидание ответа

**Состояние задачи:**
```
Теги: [ba_pending, feature, high, sales]
Статус: Ждёт выполнения
Исполнитель: ИИ Бизнес-аналитик
```

**Триггер для продолжения:** Новый комментарий от постановщика

**Напоминание:** Если ответа нет 24 часа, бот отправляет напоминание.

---

### Этап 5: Получение ответа

Пётр отвечает в комментариях:

```markdown
1. Цель - контроль выполнения плана продаж за месяц
2. Нужны: объём в рублях, количество сделок, % выполнения плана
   по каждому менеджеру отдела розничных продаж
3. Период - текущий месяц и сравнение с прошлым
4. Формат - таблица в Битрикс + выгрузка в Excel
5. Доступ - руководители отделов и директор
6. Еженедельно по понедельникам
```

**Действие:** Бот меняет тег `ba_pending` → `ba_analyzing`

---

### Этап 6: Формирование ТЗ

ИИ анализирует ответы и формирует полное описание:

```markdown
## Отчёт по выполнению плана продаж

### Цель
Еженедельный контроль выполнения плана продаж
отделом розничных продаж.

### Требования к отчёту

**Данные:**
- Объём продаж в рублях
- Количество закрытых сделок
- Процент выполнения месячного плана
- Детализация по каждому менеджеру

**Период:**
- Текущий месяц (нарастающим итогом)
- Сравнение с аналогичным периодом прошлого месяца

**Формат вывода:**
- Таблица в разделе "Отчёты" Битрикс24
- Возможность выгрузки в Excel

**Доступ:**
- Менеджеры отдела (свои данные)
- Руководители отделов (все данные отдела)
- Директор (полный доступ)

### Регулярность
Автоматическая генерация каждый понедельник в 09:00

### Критерии приёмки
- [ ] Отчёт показывает актуальные данные из CRM
- [ ] Есть фильтрация по менеджерам
- [ ] Работает выгрузка в Excel
- [ ] Настроена автоматическая генерация

---
*ТЗ сформировано ИИ Бизнес-аналитиком*
```

**Новая оценка полноты:** 85/100 → достаточно!

---

### Этап 7: Завершение работы бота

**Действия бота:**

1. Обновляет описание задачи
2. Проставляет теги классификации: `feature, high, frontend, sales`
3. Меняет служебный тег: `ba_analyzing` → `ready_to_work`
4. Отправляет уведомление постановщику:

```markdown
Пётр, ТЗ для задачи #12345 "Добавить отчёт по продажам" готово!

Задача готова к передаче исполнителю.
Пожалуйста, назначьте разработчика.

Теги: feature, high, frontend, sales

---
*ИИ Бизнес-аналитик*
```

---

### Этап 8: Передача исполнителю

**Пётр** меняет исполнителя с бота на реального разработчика:
```
Исполнитель: ИИ Бизнес-аналитик → Сидоров Алексей
```

**Бот** получает событие об изменении, видит что:
- Тег `ready_to_work` установлен
- Он больше не исполнитель

**Действие:** Бот прекращает мониторинг этой задачи.

## Сценарий B: Бот как соисполнитель

### Отличия от сценария A:

1. **Исполнитель уже назначен** - Сидоров Алексей
2. **Бот добавлен соисполнителем** - для помощи в сборе требований

```
Заголовок: Добавить отчёт по продажам
Исполнитель: Сидоров Алексей ← реальный разработчик
Соисполнители: [ИИ Бизнес-аналитик] ← БОТ
```

### Процесс тот же, но завершение другое:

После формирования ТЗ бот:
1. Ставит тег `ready_to_work`
2. Уведомляет **исполнителя** (Алексея):

```markdown
Алексей, ТЗ для задачи #12345 готово!

Пожалуйста, ознакомьтесь с описанием и подтвердите
принятие задачи комментарием "Принято" или подобным.

---
*ИИ Бизнес-аналитик*
```

3. Ждёт подтверждения от исполнителя
4. После подтверждения - удаляется из соисполнителей

## Служебные теги (жизненный цикл)

| Этап | Тег | Описание |
|------|-----|----------|
| Бот получил задачу | `ba_analyzing` | Идёт анализ |
| Отправлены вопросы | `ba_pending` | Ждём ответа постановщика |
| Получен ответ | `ba_analyzing` | Обрабатываем ответ |
| ТЗ готово | `ready_to_work` | Можно передавать исполнителю |
| Пропуск | `skip_ba` | Бот не трогает задачу |

---

## Итоговый результат

### До обработки ботом:
- Описание: 5 слов
- Теги: 0
- Исполнитель: Бот (временно)

### После обработки ботом:
- Описание: Структурированное ТЗ с критериями приёмки
- Теги: `ready_to_work, feature, high, frontend, sales`
- Исполнитель: Реальный разработчик

### Метрики эффективности

| Метрика | До | После |
|---------|-----|-------|
| Слов в описании | 10-15 | 150-300 |
| Задач с тегами | 20% | 100% |
| Время на уточнение | 2-3 дня | 4-6 часов |
| Переоткрытие из-за недопонимания | 30% | 5% |
